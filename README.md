# GrowthPulse — Attribution & Forecasting Lab

An interactive growth analytics product backed by a reproducible Python pipeline. It demonstrates multi-touch attribution, cohort retention, campaign efficiency, forecasting, anomaly flags, and data-quality checks using **synthetic data only**.

## Why this exists

Growth teams often see different answers in channel dashboards, manual trackers, and warehouse tables. GrowthPulse makes the attribution rule visible, keeps the event path inspectable, and shows how source-data checks affect decisions.

## Run locally

```bash
python pipeline/build_demo.py
python -m http.server 8000 --directory app
```

Open `http://localhost:8000` in a browser. The dashboard reads `app/data/demo.json`, generated by the pipeline. No API keys or paid services are required.

## What it demonstrates

- First-touch, last-touch, and linear attribution side by side
- Channel, time-window, and attribution-model filters
- Spend, attributed revenue, ROAS, paid orders, and CAC
- Cohort retention matrix and a 14-day trend-plus-weekday baseline forecast
- Campaign and data-quality alerts with a traceable synthetic journey
- A Python pipeline that generates source events, validates UTM fields, detects duplicate rows, computes measures, and writes a dashboard-ready JSON snapshot
- A Databricks-compatible PySpark notebook for the same synthetic event schema

## Project map

- `app/` — dependency-free interactive dashboard
- `pipeline/build_demo.py` — deterministic synthetic-data pipeline and analytics
- `databricks/growthpulse_pipeline.py` — notebook-style Spark/Delta adaptation guide
- `docs/` — metric definitions, architecture, and data contract

## Rebuild the demo data

```bash
python pipeline/build_demo.py --seed 42
```

The output includes a synthetic `demo.json` snapshot and a small raw touchpoint sample. The generator intentionally plants a few tracking defects so the quality report has something concrete to detect. The records do not represent any real company, person, customer, or campaign.

## Metric notes

- Attribution is a reporting rule, not proof of causal lift.
- ROAS uses attributed revenue divided by observed media spend for the selected period.
- The forecast is a transparent baseline, not a production demand-planning model.
- Anomaly flags prompt investigation; they do not establish root cause.

## Extend it

Replace the synthetic source with an authorized warehouse export, add a consented connector, or adapt the notebook to a Databricks workspace. Keep credentials in environment variables or the platform secret store; never commit them.
